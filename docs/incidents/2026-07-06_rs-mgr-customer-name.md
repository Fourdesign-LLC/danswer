# 調査報告: RS Mgr. 最近のエントリーで顧客名が「データなし」表示になる件

- 報告日: 2026-07-06
- 調査手段: OWLCAS MCP API(顧客・注文・S&HF・RSManager出荷データ)、Slack履歴(#_information_system / #_development)
- 制約: RSManager本体のソースコード・DBには本セッションからアクセス不可(リポジトリがセッションスコープ外)

## 結論(サマリー)

1. **上流データは無傷。** OWLCAS・S&HF Manager側では、直近の全エントリー(IV202607-0001〜0009 ほか)に顧客名が正しく入っている。顧客名の「実データ消失」は起きておらず、RS Mgr.の**表示層での名前解決の失敗**である。事業継続性の観点では、出荷・入金・請求データに欠損はない。
2. **本日未明のDNS移行事故が直近の最有力原因。** 2026-07-06 3:13 JST、fourdesign.co.jp のネームサーバーが onamae.com(dnsv.jp)から Cloudflare に切替された際、**`rsmanager-hasura`(RSManager用Hasura)を含む8レコードが新ゾーンに未登録のまま切替**され、RSManagerのバックエンドが約6時間名前解決不能だった(9:30頃 全件登録・復旧確認済み)。この間および直後、RS Mgr.画面はエントリー自体は表示できても、顧客名などの参照データの取得に失敗し「データなし」となった可能性が高い。
3. **構造的な第2要因: 顧客コードで解決できないエントリーの増加。** RS Mgr.のエントリーはDB上「顧客コードのみ」を保持し、顧客名は表示時にマスター参照で解決している(MCP経由のRSManagerデータに顧客名フィールドが存在しないことから確認)。直近エントリーには以下のようにマスターで解決できないコードが集中しており、これらは恒常的に「データなし」になり得る:

| IV番号 | 作成日 | コード | OWLCAS顧客マスターでの解決 |
|---|---|---|---|
| IV202607-0009 | 7/6 | C8223 | ✗ 配送先コード(実顧客 C1139 KOBO LLC) |
| IV202607-0002 | 7/3 | C8184 | ✗ 配送先コード(実顧客 C0664 East Fork Pottery) |
| IV202606-0016 | 6/22 | C3178 | ✗ 404 Customer not found(HEY JUDE GOODS/faire経由) |
| IV202606-0015 | 6/22 | C3159 | ✗ 404 Customer not found(OUTLANDER CONCEPT STORE) |
| IV202606-0013 | 6/22 | C5775 | ✗ 配送先コード(実顧客 C2775 Handcrafted Modern) |

   ※配送先コード建てのIV自体は5月以前から存在する(C8503, C5925, C6064等)。「最近になって顧客名が出なくなった」のであれば、RS Mgr.側の名前解決経路(参照先マスターまたは同期処理)が最近変わった・止まった可能性が高い。6/23のPR#114以降のモノレポ移行(Hasura→tRPC)で顧客影響障害が既に3件発生しており、RS Mgr.周辺も同じ移行対象領域にある。

- 7/6 9:35: 復旧確認OK(rsmanager-hasura healthz OK)。13:49 のヘルスチェックは全項目正常。

## 推奨対応

### 即時(業務継続)
1. RS Mgr.をリロードし、「データなし」だったエントリーの顧客名が復活しているか確認する(DNS事故起因分は復旧済みのはず)。
2. それでも「データなし」が残るエントリーは、IV番号でS&HF Manager(または上表)を参照すれば顧客名が判明する。業務(出荷・入金消込)はコード+S&HF参照で継続可能。
3. クライアント側のDNSネガティブキャッシュが残る端末では復旧後もしばらく失敗し得る。改善しない端末は再起動またはDNSキャッシュクリア。

### 恒久対策(RSManagerリポジトリでの修正が必要・本セッションのスコープ外)
1. **顧客名の非正規化保存**: エントリー作成時に受信ペイロードの顧客名をRSManager DBに保存する(S&HF Managerと同方式)。表示時のマスター参照依存をなくし、マスター欠落・API断でも名前が消えない構造にする。
2. **配送先コードの解決フォールバック**: 顧客マスターに無いコードは配送先(shipping address)テーブル→実顧客名で解決する(OWLCAS APIは既にこのフォールバックを実装済み。`searched_as_sa` 参照)。
3. **「データなし」の可視化**: 名前解決失敗を無音で「データなし」表示にせず、エラーとして検知・通知する(7/5の障害報告の教訓「エラーの無音化はやらない、検知を殺す」と同旨)。
4. DNSゾーン台帳(docs-internal systems/fourdesign-dns-zone_仕様書.md)の運用徹底(7/6事故の再発防止)。

- IV202606-0015/0016 は hasInvoiced=false・paymentTerm空のまま2週間経過しており、滞留の可能性あり。
